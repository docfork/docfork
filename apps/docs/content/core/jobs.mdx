The Jobs page tracks every indexing run for your private libraries. Use it to monitor progress, diagnose failures, and re-trigger indexing after changes.

Go to [app.docfork.com/jobs](https://app.docfork.com/jobs) to view your jobs.

<Callout type="info">
  Jobs only exist for private libraries. Public libraries in the Docfork catalogue are indexed
  automatically — no job is created for them in your workspace.
</Callout>

## When a job is created

A job is created when you:

- Add a new private library (indexing starts immediately)
- Trigger re-indexing from a library's detail page

## Job statuses

Each job moves through a pipeline from queued to completion:

| Status        | Meaning                                                       |
| ------------- | ------------------------------------------------------------- |
| **Queued**    | Job is waiting for a worker to pick it up                     |
| **Indexing**  | Worker is cloning the repository and extracting documentation |
| **Uploading** | Chunks are being embedded and written to the search index     |
| **Completed** | All chunks are indexed and available for search               |
| **Failed**    | Job encountered an error — see the job detail for specifics   |

## Filtering jobs

The toolbar lets you narrow the list by:

- **Status**: active, completed, or failed
- **Library**: filter to a specific private library
- **Date range**: from/to date window

Filters are preserved in the URL so you can bookmark or share a filtered view.

## Job detail

Click any row to open the job detail page. It shows:

- **Pipeline stepper**: which stage the job is at (Queued → Indexing → Uploading → Completed)
- **Overview**: library identifier, created / started / completed timestamps, and total duration
- **Indexing Results**: files scanned, files indexed, files failed, chunks created, chunks uploaded
- **Performance** — a waterfall breakdown of time spent per phase (Clone, Extract, Chunk, Embed, Upload, Finalize)
- **Failures**: individual file errors, when present
- **Output**: result or error message from the worker

While a job is active, the detail page auto-polls for updates. You can adjust the poll interval (3s, 5s, 10s, 30s) or turn it off.

## Re-indexing

From the job detail page, click **Re-index** on any completed or failed job to queue a new run for that library.

Re-indexing is also available directly from the library's detail page. Re-indexing an unchanged repository doesn't consume your monthly indexing budget — only changed content counts.

## Troubleshooting failures

If a job fails:

1. Open the job detail and check the **Failures** panel for per-file errors
2. Check the **Output** section for the worker's error message
3. Common causes: repository access revoked (PAT expired or GitHub App uninstalled), repository moved or renamed, or source files that can't be parsed
4. Fix the underlying issue, then click **Re-index**
